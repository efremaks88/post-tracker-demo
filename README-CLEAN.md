# ПОСТ ТРЕКЕР

Создано Максимом Ефремовым. Версия 1.4.2.

Чистая переносимая копия проекта без рабочей базы данных, учетных записей, логов, кешей, git-истории и внутренних заметок.

## Что внутри

- frontend: `src/index.jsx`, `public/app.js`, `public/app.css`, локальные React vendor-файлы;
- backend: `server.js`, `routes/`, `lib/`;
- SQL-миграции: `migrations/`;
- служебные проверки и build: `scripts/`, `build.js`;
- пример окружения: `.env.example`.

## Что специально убрано

- `.git`, `node_modules`, `.agents`, `.codex`;
- рабочая база данных и пользовательские данные;
- внутренний файл структуры данных и личный wishlist;
- серверные IP/домены/брендовые привязки заменены на example-значения.

## Быстрый запуск на новой машине

1. Установить Node.js 20.12+ и PostgreSQL.
2. Выполнить `npm ci`.
3. Создать базу; приложение применяет SQL-миграции при запуске.
4. Скопировать `.env.example` в `.env` и заполнить реальные значения.
5. Выполнить `npm run build`, затем `npm start`.

Файл `.env` загружается при запуске. Для SQL-версии пока требуется доступный LDAP-каталог.
Для локального просмотра без SQL и LDAP запустите `Start-Demo.cmd` в родительской папке.
Демонстрационные данные хранятся отдельно и не входят в исходный архив.

Проверки: `npm test`, `npm run check`, `npm run security:smoke`.
Тесты SQL используют отдельную PostgreSQL-базу PGlite в памяти и не подключаются к рабочей базе.
Массовое сохранение требует текущую `_revision` из `GET /api/data`; устаревшие снимки возвращают 409.

В 1.4.2 исправлены сохранение отмены создания, история быстрых изменений,
защита несохранённого состояния, связанные удаления и средняя плановая нагрузка.
Проверки React включают реальные обработчики App через react-test-renderer;
это не визуальные или DOM-тесты браузера.
