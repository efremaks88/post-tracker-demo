# A4: единая политика прав

## Что изменилось

Серверные маршруты теперь используют единый модуль `lib/policy.js`. Он отвечает на два вопроса: разрешено ли действие роли и к каким проектам относится доступ пользователя. Существующие RBAC-роли и таблица `user_projects` сохранены; менеджерский доступ по ответственным проекта также остаётся действующим.

Будущие разрешения `finance.view`, `contracts.view` и `approval.decide` уже имеют стабильные имена, но не выданы ни одной роли, включая администратора. Финансовые и договорные данные и API на этом этапе не создавались.

## Как подключать новые API

Новый серверный маршрут должен сначала требовать авторизацию, затем конкретное разрешение через `requirePermission`. Для объекта проекта дополнительно используется `policy.can(..., POST_PROJECT_VIEW/POST_PROJECT_EDIT, {projectId})`. Закрытый ответ формируется отдельным маршрутом и не добавляется в общую выгрузку `/api/data`.

Новая роль или выдача будущего разрешения требует отдельного продуктового решения, изменения матрицы и тестов границ доступа. Отсутствующее разрешение всегда означает запрет.
